║                                         KEY DESIGN PATTERNS                                                   ║
╠════════════════════════════════════════════════════════════════════════════════════════════════════════════════╣
║                                                                                                                ║
║ 1. PROJECT PACKAGE PATTERN                                                                                   ║
║    All artifacts (inputs, configs, scripts, outputs, logs) packaged together in one directory.              ║
║    Benefits: Reproducibility, portability, self-contained submission                                        ║
║                                                                                                                ║
║ 2. PATH TRANSFORMATION PATTERN                                                                              ║
║    Spec paths transform: Local ──sync──> Remote ──configure──> Taiji ──execute──> Results                 ║
║    All relative paths work identically at every stage (configs/, outputs/, scripts/ relative to package)   ║
║                                                                                                                ║
║ 3. SPLIT ANALYSIS PATTERN (Default)                                                                         ║
║    GPU generation on Taiji (expensive, accelerated)                                                         ║
║    Analysis filtering on local workstation (cheap, flexible)                                                │
║    Benefits: Fast GPU turnaround, local iteration, resource efficiency                                      ║
║                                                                                                                ║
║ 4. SPEC MATERIALIZATION PATTERN                                                                            ║
║    Every stage writes JSON/YAML files for inspection:                                                       ║
║    ├─ 01_design_parameter_plan.yaml        (parameters)                                                    ║
║    ├─ 02_taiji_simple_config.json          (Taiji submission)                                            ║
║    ├─ 03_run_monitor_snapshot.json         (execution status)                                             ║
║    ├─ 04_result_ingestion.json             (collected outputs)                                            ║
║    ├─ 06_evaluation_summary.json           (scores & analysis)                                            ║
║    └─ 07_next_round_proposal.json          (new parameters)                                               ║
║    Benefits: Full auditability, debugging, reproducibility                                                 ║
║                                                                                                                ║
║ 5. CEPH MOUNTING PATTERN                                                                                    ║
║    Taiji container receives CEPH_SECRET via env var                                                        ║
║    Startup script mounts /aceph/daweihuang if not already mounted                                          ║
║    BoltzGen accesses all files via Ceph (package, checkpoints, cache)                                      ║
║    Benefits: Centralized data, no network latency, automatic retry logic                                   ║
║                                                                                                                ║
║ 6. REMOTE PROJECT DIR PATTERN                                                                               ║
║    Taiji config contains "remote_project_dir" = Ceph package path                                          ║
║    Startup command sets WORKSPACE = remote_project_dir                                                      ║
║    Script execution happens from package root (reproducible relative paths)                                 ║
║    Benefits: Clear semantic separation, portable configuration                                              ║
║                                                                                                                ║
